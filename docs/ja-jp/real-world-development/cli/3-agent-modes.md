最初に、プロジェクトへ小さな機能を追加しました。より大きな変更には、より堅牢なプロセスが必要です。GitHub Copilot CLI は組織の既存の開発フローに沿って動作するため、適切なものを適切な方法で構築できます。このレッスンから、エージェントを活用した一般的な開発プロセスを数回に分けて進めます。まず issue をもとに新機能を作成し、コードが有効で機能が想定どおりに動作することを確認し、最後にプロジェクトへマージします。

> [!NOTE]
> 機能開発の間は、同じ会話とブランチを使います。通常は作業するファイルの種類ごとに別のブランチや PR を使いますが、ここでは主要な概念に集中できるよう手順を簡略化します。

このレッスンでは、次のことを行います。

- GitHub issue から Copilot の新しい会話を開始します。
- Plan モードで要件を定義します。
- Autopilot モードで新機能を実装します。
- コードを確認します。
- 転送されたブラウザーで機能を手動検証します。

この機能の開発を続けながら、リポジトリの指示を更新し、既存の `quality-checks` skill をカスタマイズし、MCP による検証を追加し、QA エージェントを作成して、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログが増え、訪問者はカテゴリやパブリッシャーでゲームを絞り込む必要があります。バックログの issue には機能が記載されていますが、カテゴリの組み合わせなど、コーディングの前に合意が必要な詳細があります。Plan モードでそのような決定を行い、Autopilot に範囲を限定した実装を許可します。

## 背景

人工知能 (AI) コーディング エージェントを開発フローに導入しても、基本は変わりません。むしろ、基本がさらに重要になります。多くの開発者は、次のような流れで作業します。

1. 必要な作業を記載した issue を起点にします。
2. 実装内容を計画します。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新しい機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードがレビューされ、継続的インテグレーション プロセスが成功したら、コードをマージします。

> [!NOTE]
> 詳細はチームや組織によって異なりますが、ほとんどのプロセスは上記の流れに沿っています。

この標準的な手順に従うことで、AI が生成したコードが要件を満たし、手書きのコードと同じ審査プロセスを通過するようにできます。

## 会話モード

**会話モード**は、エージェントにどの程度の自律性を与えるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押してモードを切り替えます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更を提案し、続行する前に入力を待ちます。
- **Plan**: エージェントが最初に計画を作成し、プロジェクト ファイルの編集は行いません。
- **Autopilot**: エージェントが自律的にコードを書き、テストを実行し、タスクの完了を判断するまで反復します。

Plan モードで開始し、計画を確認してから Autopilot で実装します。

## issue から開始する

フィルタリングの作業を始める前に Codespace に戻り、リポジトリとターミナルが準備できていることを確認します。

1. Codespace に戻ります。停止している場合は、続行する前に再起動します。
2. 星評価の PR がマージされていることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新して、フィルタリング作業用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての issue を表示します。
8. 矢印キーを使って、**Allow users to filter games by category and publisher** というタイトルの issue を選択します。
9. <kbd>C</kbd> を押して issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトの先頭が `#7` (または同様の番号) になっていることを確認してください。`#` を使うと、GitHub の issue やプルリクエスト (PR) をコンテキストに追加できます。

## フィルタリング機能を計画する

計画を立てると、機能を実装したりタスクを実行したりする前に方針を決められます。複雑な作業では、時間をかけて計画することをお勧めします。Plan モードに切り替えて、Copilot に計画を作成してもらいましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** になっていることを確認します。
2. 前の手順で追加した issue の参照に続けて、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot が計画の作成を開始します。最初にプロジェクトを調査し、その後、最適な方針を判断します。

3. フィルタリングの動作について質問されることがあります。希望に基づいて回答してください。間違った答えはありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 上下にスクロールして計画を確認します。
6. 自分の決定と異なる部分があれば、Copilot に修正を依頼します。

## Autopilot を承認する

計画を作成して確認したら、実装に進みます。Autopilot を使って Copilot に作業を任せましょう。

Autopilot を使うと、Copilot は問題が完了したと判断するまで繰り返し作業します。

1. **Accept plan and build on autopilot (recommended)**、またはインストール済みバージョンで同様の名前のオプションを選択します。
2. プロンプトの下にあるモード表示が **Autopilot** になっていることを確認します。
3. Copilot が合意済みの計画に沿って反復し、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認するとすぐに実装が始まる場合があるため、先に計画を確認してください。Copilot が依存関係の不足やポートの競合を報告した場合は、チェックを完了とみなす前にセットアップの問題を解決します。

## 実装を確認して検証する

コードが生成されたら、他のコードと同じようにマージ前に確認します。コードをレビューし、サイトを実行して問題がないことを確認しましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示が **Plan** または **Autopilot** ではないことを確認します。
2. `/diff` を入力し、フィルタリングの実装とテストを確認します。
3. 結果を issue および計画中に決めた内容と照らし合わせます。
4. コードの確認が終わったら、<kbd>Esc</kbd> を押して差分ビューを閉じます。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に修正を依頼します。

## 新しい機能を試す

コードはよさそうですが、実際に動くでしょうか。以前と同じようにアプリを起動し、Codespaces の転送ポートからサイトを開きます。

1. Copilot にアプリの起動を依頼します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces でポート `4321` が使用可能になったら、**Open in Browser** を選択します。
3. カテゴリでの絞り込み、パブリッシャーでの絞り込み、計画で合意した組み合わせを試します。
4. リセットと検索結果がない場合の動作が、issue と決定内容に合っていることを確認します。
5. Codespace に戻り、起動した開発サーバーを停止するよう Copilot に依頼します。

- Autopilot モードで新機能を実装しました。
