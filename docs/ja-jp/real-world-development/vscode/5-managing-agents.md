GitHub Copilot をエージェントモードで使うと、コードベースを調べ、変更を提案し、ファイルを編集して、コマンドを実行するなど、自律的に作業します。VS Code の Copilot Chat では、作業が手元のマシンでリアルタイムに進むため、各ツールの呼び出しやファイル編集を逐次確認できます。差分をその場でレビューし、個別の変更を承認または却下して、エディターを離れずに追加のプロンプトで会話を誘導し、作業を調整または拡張できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- 作業中のエージェントにライトモードの切り替えを追加するよう依頼します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントが、ハイコントラストモードを実装しています。作業中に、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザーのために、ライトモードの切り替えも追加したいとのことです。新しい会話を最初から始めず、進行中のセッションに追加の作業を依頼します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調べたファイル、実行したコマンド、提案した編集などを確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められるターミナルコマンドなどが表示されます。
3. エージェントがファイル編集を提案すると、差分がチャット内に表示されます。
    - **Keep** を選択すると、変更を適用します。
    - **Undo** を選択すると、変更を元に戻し、エージェントにもう一度対応してもらいます。
4. チャット上部の **Files changed** 表示を開くと、このセッションでエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などでツールの使用許可を求められると、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可できるコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。実施した変更をまとめた最終メッセージが表示されます。

## ライトモードを追加するようエージェントを誘導する

ハイコントラストモードができたら、同じ会話にライトモードの切り替えを追加します。同じチャットセッションを続けるため、エージェントはこれまでの作業、変更したコンポーネント、スタイルの方法、ローカルストレージの使用方法などのコンテキストを保持します。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントはすでに行った変更を調べ、ライトモードの追加を提案します。
3. ハイコントラストモードのときと同じように、新しい編集を確認します。差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの進め方が希望と異なる場合（たとえば、気に入らない方法で切り替えユーザーインターフェイス (UI) をリファクタリングしようとする場合）は、チャット入力欄の横にある **Stop** ボタンで停止し、説明を追加したフォローアップメッセージを送信します。

> [!TIP]
> 進行中のセッションを誘導する方が、最初からやり直すよりもすばやく進められます。フォローアッププロンプトで変更を依頼できます（「カスケーディングスタイルシート (CSS) を簡潔にしてください。セレクターを重複させず、CSS 変数を使ってください」）、方向を修正できます（「3 つ目の切り替えを追加せず、既存の設定パネルにライトモードを追加してください」）、作業範囲を広げることもできます（「両方の切り替えにキーボードショートカットも追加してください」）。

## 作業内容を確認する

変更をコミットする前に、エージェントが編集した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが表示されます。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントから伝えたアクセシビリティのパターンが反映されていることを確認します。Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティックなハイパーテキストマークアップ言語 (HTML)、ローカルストレージによる設定の保持などを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

このレッスンでは、Copilot Chat のエージェントモードを使って進行中のセッションを監視し、方向を調整しました。ファイル編集を確認しながら適用または却下し、コンテキストを保ったまま追加プロンプトを送信して作業を拡張しました。

- アクセシビリティエージェントの作業をリアルタイムで監視しました。
